日志上传与读取接口

当前部署把 Story Painter 前端和日志后端放在同一个 Node 服务内。 API 保持两套路径前缀兼容，旧客户端和新客户端可以指向同一个域名。

兼容路径前缀
/api/dice
/dice/api

端点

下方路径可把 `/api/dice` 等价替换为 `/dice/api`。

PUT
/api/dice/log
余烬核心上传日志。请求体为 multipart/form-data。
POST
/api/dice/w4123
w4123/Dice 插件兼容接口，支持 multipart/form-data 或 JSON。
GET
/api/dice/load_data?key=AbCd&password=123456
根据上传返回的 key 和 password 读取日志数据。
PUT
/api/dice/backup-upload
备用上传桥接接口，主存储失败时可级联转发。
GET
/healthz
服务健康检查。
GET
/metrics
Prometheus 文本格式指标；默认关闭，开启后可配置 Bearer token。

管理端接口

以下接口需要先通过 `/admin/api/login` 获取管理会话。

GET
/admin/api/logs
按 SQLite 元数据分页列出日志；`q` 只筛选名称、key、IP和时间。
GET
/admin/api/logs/:key/raw
导出原始存储 JSON。
POST
/admin/api/logs/delete
批量删除日志，请求体为 `{ "keys": ["AbCd#123456"] }`。
POST
/admin/api/cleanup
按留存天数手动清理过期日志。
POST
/admin/api/database/maintenance
执行 SQLite integrity_check 和 WAL checkpoint，可选 `{ "vacuum": true }`。

请求字段

文件上传默认限制为 5 MB，可通过配置调整；`uniform_id` 需要符合 `来源:标识` 格式。

multipart/form-data

name 日志名称。
uniform_id 上传方统一 ID，例如 `seal:123456`。
file 日志文件，默认最大 5 MB。

backup-upload JSON

name 日志名称。
uniform_id 上传方统一 ID。
logdata Base64 编码后的压缩日志数据。
visitedHosts 可选，用于级联转发时避免循环。

示例

在一体化部署中，示例里的域名可以直接使用当前服务地址。

上传日志 
curl -X PUT http://localhost:3000/api/dice/log \
  -F 'name=demo.txt' \
  -F 'uniform_id=seal:123456' \
  -F 'file=@demo.txt'
读取日志 
curl 'http://localhost:3000/dice/api/load_data?key=AbCd&password=123456'

响应与状态

上传成功后返回的 URL 会指向当前前端页面。

{
  "url": "http://localhost:3000/?key=AbCd#123456"
}
200 请求成功。
400 字段缺失或格式不正确。
404 读取的日志不存在。
413 文件超过大小限制。
422 上传内容命中安全拦截规则，返回纯文本警告且不会写入日志。
